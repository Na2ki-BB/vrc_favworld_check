# 画像込みバックアップ仕様

「バックアップを書き出す」で作るZIPと、ZIP・従来JSONの復元条件を定義します。操作方法は[README](../README.md#保存データとバックアップ)、非表示・完全削除との関係は[記録管理仕様](RECORD_MANAGEMENT.md)を参照してください。

実装は [`backup-archive.js`](../extension/lib/backup-archive.js)、[`backup.js`](../extension/lib/backup.js)、[`database.js`](../extension/lib/database.js) です。

## 書き出す内容

表示中の1アカウントについて、ワールド、リスト、変更履歴、非表示状態、完全削除済みID、自動確認・通知の設定と、ワールド記録に対応する保存済みWebPサムネイルを同じ読み取りトランザクションから取得します。

- 画像を新たに取得せず、Chrome内の保存済み画像だけを書き出します。画像0件でもZIPを作れます。
- 取得待ち・取得失敗で保存されていない画像や、現在のワールド記録に対応しない孤立画像は含みません。孤立画像はローカルから削除しません。
- 上限超過や対象データの不整合では書き出しを失敗させます。対象の記録や画像を黙って省略しません。
- Cookie、パスワード、2FAコード、トークン、生のAPI応答、ログ、署名付き転送先URLは含めません。
- 画像取得ジョブ、未読追跡、通知キュー、通信の待機期限、次回実行予定、選択中プロフィールなどの端末運用状態は含めません。

記録と画像索引は、許可したフィールドだけから新しいオブジェクトを作ります。バックアップは暗号化していません。

## ファイル形式

圧縮しないstored ZIPを使い、次のファイルだけを許可します。

```text
backup.json
thumbnails/index.json
thumbnails/<world-id>.webp
```

`backup.json` は `vrc_favworld_check-backup` のversion 3です。単独でも従来のJSON検証に通る形式で、`worldDispositions` に非表示・完全削除済みIDを含みます。

`thumbnails/index.json` のフィールドは次のものに限ります。

| フィールド | 内容 |
| --- | --- |
| `format` | `vrc_favworld_check-image-backup` |
| `version` | `1` |
| `userId` | `backup.json` と同じUser ID |
| `thumbnails` | 画像ごとの索引配列 |

各画像の索引は `worldId`、`path`、`width`、`height`、`byteLength`、`capturedAt`、`sourceUrl` だけを持ちます。`path` は `thumbnails/<worldId>.webp`、`sourceUrl` は許可済みの元VRChat API画像URL、`capturedAt` は正規化されたUTC日時です。索引・画像・ワールド記録の対応を必須にします。

| 上限 | 値 |
| --- | --- |
| ZIP全体 | 64MiB |
| `backup.json` | 25MiB |
| `thumbnails/index.json` | 5MiB |
| 画像 | 10,000件、1件48KiB、幅・高さ各320px |
| ワールド／履歴／リスト／表示状態 | 10,000件／100,000件／100件／10,000件 |

ZIPの書き出しでは、画像Blobの読み込みと出力領域の確保に先立って、全画像の管理情報とZIP全体の容量を検査します。読み込みでは、入力容量と全entryの領域の重なりを先に検査し、重複した領域のコピーやCRC計算による増幅を防ぎます。

画像件数はZIPに入る対象画像に適用します。データベースの読み出しでは孤立画像のBlobを保持せず、対象画像を上限+1件まで集めた時点で停止します。容量を計算する単位は1MiB = 1,048,576バイト、1KiB = 1,024バイトです。

## 復元と既存データ

「バックアップを復元する」はZIPと従来のJSON version 1・2・3を受け付けます。確認画面に対象アカウント、ワールド・履歴・画像の件数、書き出し日時と置き換える内容を表示します。

- 書き込み前にZIP構造、記録、索引と画像を検証し、画像はブラウザのデコーダーでも確認します。
- 利用者の確認後、対象アカウントのワールド・リスト・履歴・表示状態・削除済みIDを置き換えます。他アカウントの記録は変更しません。
- 設定は明示されたboolean値の `autoSyncEnabled` と `notificationsEnabled` だけを反映します。この2項目は拡張共通の設定です。端末運用状態は取り込みません。
- ZIP内の画像は追加・更新し、バックアップにない既存画像は保持します。ただし、復元する `worldDispositions` が `purged` のIDの画像は消去します。

記録・設定・表示状態と画像の変更は、1つのIndexedDBトランザクションで確定します。検証失敗時は書き込みを始めず、トランザクション中の失敗時は全体を取り消します。

従来のJSONには画像がありませんが、既存画像を保持する条件と、完全削除済みIDの画像を消去する条件は同じです。旧形式にない表示状態は通常表示に戻ります。古いバックアップに記録が含まれていれば、完全削除した名前や履歴が戻る場合があります。

復元した過去の通知は再送せず、未読をリセットします。対象アカウントの古い画像取得ジョブを破棄し、データ世代を更新して古い処理からの書き込みを拒否します。復元自体ではVRChat APIや画像の取得を開始しません。

## 入力の安全境界

一般的なZIP展開処理を使わず、専用パーサーで対応形式だけを読みます。

- UTF-8名・stored方式だけを許可し、圧縮、暗号化、data descriptor、extra field、comment、multi-disk、Zip64を拒否します。
- 絶対パス、ドライブ名、`.`、`..`、空のパス要素、バックスラッシュ、未知・重複entryを拒否します。
- local/central headerの名前・方式・CRC・サイズとlocal offsetの整合を検査します。重なり、隙間、末尾などに隠れたデータを拒否します。
- 全entryのCRCを検査します。CRCは破損検査であり、作成者の証明や改ざん防止機能ではありません。
- 索引にない画像、実体がない索引、別アカウント・未知ワールド・重複World IDの画像を拒否します。
- 記録JSONにも従来の型、文字数、件数、ID、日時、参照関係、許可フィールドの検査を適用します。
- WebPのRIFF全長・chunk境界・静止画VP8/VP8L本体・寸法・byte数を検証します。VP8Xの寸法ヘッダーだけの画像やアニメーションは受け付けません。
- 書き込み前に各画像をブラウザでデコードし、索引の寸法と再照合します。デコードできなければ既存データを変更しません。1件のデコードは10秒で中止し、検証中に画面を閉じた場合も書き込み開始前に中止します。

検証には人工的な記録と画像を使用します。実利用者の履歴、画像、Cookie、署名付きURL、バックアップをリポジトリやテスト用ファイルに含めません。自動テストの対象は [`backup-archive.test.js`](../tests/backup-archive.test.js)、[`backup-ui.test.js`](../tests/backup-ui.test.js)、[`backup.test.js`](../tests/backup.test.js)、[`database.test.js`](../tests/database.test.js) です。実Chromeでのデコード・表示・操作確認は[開発ガイド](DEVELOPMENT.md#配布前の実機確認)に従います。
