# Windowsインストーラー仕様

Windowsインストーラーの配置、更新、削除、安全上の境界を説明する。利用者向けの導入手順は[README](../README.md#インストール)、ビルド手順は[開発・検証・配布](DEVELOPMENT.md)を参照。

## 構成

| 項目 | 仕様 |
| --- | --- |
| 作成方式 | Inno Setup 6 |
| 定義ファイル | `installer/vrc_favworld_check.iss` |
| 対象OS | Windows 10以降（`MinVersion=10.0`） |
| 実行権限 | 現在のWindowsユーザー（`PrivilegesRequired=lowest`） |
| 配置先 | `%LOCALAPPDATA%\Programs\VRCFavoriteWorldHistory\extension` |
| 配布名 | `vrc_favworld_check-installer-v<version>.exe` |
| 同梱対象 | 検査済みの `dist/extension/` |
| アンインストール登録 | Inno Setup標準のユーザー単位登録 |

管理者権限は要求しない。製品固有の `SetupMutex` でインストーラーの同時実行を抑止する。導入先を固定し、更新時に別の読み込み元へ切り替わることを防ぐ。manifestに固定の `key` は持たないため、記録の引き継ぎには同じユーザー、Chromeプロフィール、読み込み先を維持する必要がある。

## 初回導入

1. 拡張ファイルを固定配置先へ展開する。
2. 完了画面からChromeの `chrome://extensions/` と、選択対象の `extension` フォルダーを開く。
3. 利用者がChromeの「デベロッパー モード」を有効にし、「パッケージ化されていない拡張機能を読み込む」で追加する。

インストーラー自身はChromeへ拡張を登録しない。Chromeの標準的なインストール先から実行ファイルを探し、見つからない場合は `chrome.exe` を使う。Chromeが開かない場合、利用者は手動で管理画面を開ける。

## 更新と復旧

更新前にはChromeの全ウィンドウを閉じる確認を表示する。Chromeの強制終了は行わない。

1. 既存manifestの `x.y.z` 形式のバージョンを検証する。古い版へのダウングレードは拒否し、同じ版の再インストールは許可する。
2. 新しいファイルを同じアプリフォルダーの `extension.new` へ展開する。
3. manifestのバージョンと主要ファイルの存在を確認する。
4. 現在の `extension` を `extension.old` へ退避し、`extension.new` を `extension` へ切り替える。
5. 切り替え後にも検証し、成功後に `extension.old` を削除する。切り替え・検証に失敗した場合は、旧版への復旧を試みる。

前回の中断で `extension.old` だけが残っている場合は、更新前に元の場所へ戻す。現在のフォルダーと退避フォルダーが両方存在する場合は、古い退避を整理する。バージョンや既存状態を安全に確認できない場合は、上書きを開始しない。復旧にも失敗した場合はエラーを表示する。

更新後はChromeの拡張機能画面を開き、利用者が有効状態、表示バージョン、権限を確認する。古いバージョンが残っていれば再読み込みする。ファイルの更新だけでChromeの実行中コードが切り替わったとは判断しない。

## 削除

利用者へ、拡張の設定画面で必要なJSONを書き出し、「記録をすべて削除して拡張を削除」を完了してからWindows側の削除を行うよう案内する。JSONには画像を含まないため、Chrome内の画像を消去する影響をREADMEで説明する。

Windowsアンインストーラーの削除対象は、固定アプリフォルダー内の次の項目に限定する。

- `extension`、`extension.new`、`extension.old`
- Inno Setup自身が管理するアンインストール用ファイル
- 空になったアプリフォルダー

Chrome内のデータ消去は拡張が担当する。WindowsアンインストーラーはChromeプロフィールや書き出したJSONを削除しない。

## 安全上の境界

- ブラウザポリシーや強制インストールを使用しない。
- Chromeプロフィール、Cookie、IndexedDBを探索・変更しない。
- サービス、タスクスケジューラー、スタートアップを登録しない。
- 認証、API通信、定期確認、バックアップは拡張で実行する。
- 実行時のファイルダウンロードやテレメトリーは行わない。
- Windowsへの登録はInno Setup標準のユーザー単位アンインストール情報に限定する。

配布EXEは未署名のため、Windows SmartScreenなどの警告対象になる場合がある。配布元、リリースの注意事項、公開されたSHA-256を利用者が確認できるようにする。ハッシュの一致はファイルの同一性の確認であり、コード署名や安全性の保証を代替しない。

## 検証項目

自動検査の対象は `tests/installer-config.test.js`、`tests/release-scripts.test.js`、`scripts/build-installer.mjs`。固定配置、非昇格、ダウングレード拒否、復旧処理、削除範囲、source/buildの一致などを確認する。

実際のWindowsとChromeでは、次を別途確認する。自動テストの成功を実機確認の代わりにしない。

- 新規導入とChromeへの手動追加
- 同版の再導入・既存版からの更新後の拡張ID、履歴、画像、設定の保持
- 更新の中断・復旧と、失敗時の既存ファイル保持
- Chrome再起動後の表示バージョン、権限、同期、画像取得
- 拡張内の全消去と自己削除、Windows側のアンインストール
- 配置先外のファイル、Chromeプロフィール、JSONバックアップがWindows側の処理で変更されないこと
- SmartScreenおよびChrome権限画面と利用者向け案内の整合
