# 製品仕様

VRC Favorite World Historyは、VRChatのお気に入りワールドを記録し、あとで一覧から見えなくなったときに保存済みの名前や画像を確認するためのChrome拡張です。

この文書は製品の対象範囲と、実装・検証で守る動作をまとめています。操作方法は[README](../README.md)、内部構成は[アーキテクチャ](ARCHITECTURE.md)、検証手順は[開発ガイド](DEVELOPMENT.md)を参照してください。

## 対象環境と製品の範囲

- Windows版Google Chrome 120以降の通常プロフィールで使用します
- VRChat公式サイトで成立したログインを利用し、拡張内ではパスワードや2FAコードを入力しません
- 名前、作者、お気に入りリスト、状態、履歴、縮小画像は拡張専用のIndexedDBへ保存します
- VRChat側のAPI操作は読み取り専用です。お気に入りの追加・解除やワールドの変更はしません
- 記録はVRChatアカウントごとに分離します。クラウド保存や端末間の自動同期は行いません
- 導入前の履歴や、取得する前に見えなくなった名前・画像は復元できません
- ブラウザが動作していない間は確認・通知できません。実行時刻にはChromeや端末の状態による遅れがあります

VRChatの公式製品ではありません。APIから確認できた事実を記録し、一覧欠落の理由や、削除・非公開の区別を断定しません。

## 初回利用とログイン確認

1. Windowsインストーラーで固定場所に配置した拡張を、Chromeの「パッケージ化されていない拡張機能を読み込む」から登録します
2. 同じChromeプロフィールでVRChat公式サイトへログインします
3. 「今すぐ確認」で初回記録を作ります。初回の保存を名称変更・消失・復帰として通知しません

画面の「現在のログイン確認」と、最後に成功した同期は別の情報です。ログイン確認だけではワールド記録や選択中のアカウントを変更しません。ログイン済み、ログインが必要、2FAが必要、確認不能、処理中、待機中を区別し、通信失敗をログアウトと断定しません。

認証確認には短いキャッシュを使います。認証CookieはAPI通信中だけ一時利用し、記録・通知・JSONバックアップへ含めません。既存Cookieと競合する場合や片付けを確認できない場合は処理を止めます。

## ワールドの取得と判定

### 正常な同期の条件

お気に入り関係とワールド情報を全ページ取得し、形式・ID・件数・ページの進行を検査します。取得途中の失敗や不完全な一覧で保存済みの状態を更新しません。最大8リスト・800ワールドを扱うことを検証対象とします。

主な取得は一覧APIを使い、個別確認は1回の同期で最大20件に制限します。確認待ちの対象は次回以降へ残し、1回404を確認した対象を優先します。既存の閲覧可能なワールドの不足画像は、個別確認の余った枠で補います。

### 状態の意味

| 根拠 | 状態・表示の意味 |
| --- | --- |
| 正常な一覧から1回欠落 | 確認中。確定した消失として通知しない |
| 関係一覧とワールド一覧の両方から2回連続欠落 | お気に入り一覧にない。手動で解除した場合も含む |
| 個別取得で2回連続404 | 現在アクセス不可。削除か非公開かは区別しない |
| お気に入り一覧に再出現 | お気に入りに戻ったことを記録 |
| 正常なワールド情報を再取得 | 再びアクセスできることを記録 |
| 同じIDの名前が変化 | 変更前後の名前と確認時刻を記録 |
| 所属リストのタグが変化 | 変更前後のリストを履歴に記録 |

所属状態とアクセス状態は独立しています。一方の一覧に存在するワールドを、もう一方にないだけで一覧欠落へ進めません。401、429、通信障害、5xx、応答形式不正では状態判定の連続回数を増やしません。

保存済みの名前、作者、画像は、その後取得できなくなっても保持します。同じ状態遷移から履歴を重複作成しません。

### お気に入りリスト

- 内部名と表示名を分けて保存し、リスト名の変更とワールドのリスト移動を区別します
- 所属タグはお気に入り関係を優先します。関係一覧と一括ワールド情報のタグが矛盾する場合は、以前のタグを保持し、その同期では移動履歴を作りません
- リスト名だけを安全に更新できない場合は前回の名前を保持し、ワールドの同期は可能な範囲で続けます。認証・通信・レート制限の障害では同期全体を止めます
- 通常は既知の4枠を表示します。保存済みリストまたはタグでVRC+枠の利用を確認できる場合は、未使用枠を含む8枠を番号順に表示します

## 記録画面と通知

### 見つけやすい表示

記録画面の初期表示は、非表示にしていない確定済みの一覧欠落・アクセス不可ワールドです。両方に該当する同じワールドは1件として数え、アクセス不可を優先します。

- 名前、画像、作者、最後に確認できたリスト、状態、World IDを同じカードで確認できます
- 全記録、非表示、状態、リストで絞り込み、現在名・過去名・作者名・World ID・リスト名から検索できます
- 変更履歴では名称変更、リスト移動、一覧欠落、アクセス不可、復帰を確認できます
- 要確認0件、初回、未確認、確認待ち、通信失敗を区別します。「0件」を全ワールドの現在の安全性の保証として表示しません
- 画像の保存済み件数、残り、失敗を区別します。件数を読めない場合は0件と決めつけません
- 最終正常同期から36時間以上経過した場合は、確認が止まっていることを案内します

API由来の文字列はHTMLとして解釈せず、テキストとして表示します。キーボード操作、フォーカス、狭い画面、200%拡大、長い日本語名でも操作対象を確認できることを検証します。

### 通知と未読

- **FR-NOTIFY-01** 名称変更と、確定した一覧欠落・アクセス不可・復帰をOS通知の対象にします。初回記録、1回目の候補、リスト移動はOS通知しません
- 1回の同期で複数の変化があっても、通知は最大1件へまとめます。消失系を含む場合は要確認画面、それ以外は変更履歴へ案内します
- 通知本文には件数と分類を表示し、ワールド名や利用者名を載せません
- 各イベントへの通知試行は最大1回です。OS通知の表示自体は保証せず、失敗・中断後も履歴を正本として残します
- 通知と既読は分けて扱います。リスト移動も未読に含め、変更履歴を開くと既読にします
- 旧データの削除で未読の内訳が分からなくなった場合は、数を推測せず未確定として表示します

## 自動確認と障害時の動作

| 項目 | 動作 |
| --- | --- |
| 自動確認 | 既定で有効。通常は12時間後に0〜60分の幅を加えて次回を予約 |
| 手動確認 | 原則5分間隔。同時に複数の完全同期を開始しない |
| 起動時 | 保存済みの予定を修復。期限を過ぎていれば通常1〜10分後に予約 |
| 通信障害・5xx | 短い待機で最大2回再試行し、失敗後の自動確認は30〜60分後 |
| 429 | その回の処理を止め、保存した期限までJSON API・画像取得・認証確認の新規通信を控える |
| 認証・形式の問題 | 状態更新を止め、公式サイトでの確認や再試行など次の操作を案内 |

自動確認とデスクトップ通知は個別に無効化できます。設定の保存と実行予定の修復は区別し、予定だけの修復失敗を設定保存失敗として表示しません。

## 画像の保存

サムネイルは、アクセス可能な間にVRChatの許可済み画像URLから取得し、最大辺320px・48KiB以下のWebPへ縮小して保存します。元画像と署名付き転送先URLは保存しません。

画像は名前・状態・履歴の保存後に取得します。1回に処理できる量を制限し、残りは専用アラームで続けます。通常同期の自動確認を無効にしても、開始済みの画像ジョブは継続します。ブラウザ停止後は、保存済みの対象と試行回数から再開します。

同じ保存版を繰り返し取得せず、失敗時は既存画像を保持します。同一ジョブでは各画像を最大3回試み、残った失敗を画面で案内します。保存済み画像の表示には外部URLを使いません。

## 非表示と完全削除

| 操作 | 対象と結果 |
| --- | --- |
| 一覧から削除 | 確定した一覧欠落・アクセス不可の記録を非表示にする。名前・画像・履歴・同期・通知は維持 |
| 戻す | 非表示の記録を通常表示へ戻す |
| 完全に削除 | 非表示の記録の名前・画像・全履歴・画像取得待ち情報を削除。再生成を抑止するWorld IDだけを保持 |

非表示の記録は自然に復帰しても自動表示しません。完全削除した記録は取り消せませんが、後日の完全同期で利用可能なお気に入りとして新しく確認できた場合、新規記録として保存されることがあります。古い同期結果や関係IDだけでは再作成しません。

削除は対象のアカウント・ワールドと影響を表示して確認します。確認後に対象が変化した場合や、同期・画像処理・全消去と競合する場合は実行を止めます。他のワールドとアカウントの記録は変更しません。詳細は[記録管理仕様](RECORD_MANAGEMENT.md)を参照してください。

## バックアップと保存容量

JSONバックアップは1アカウント単位で、名前、状態、履歴、リスト、非表示・完全削除済みID、安全な設定を含みます。現行形式はversion 3で、version 1・2も読み込めます。

- 復元前に形式、サイズ、ID、日時、件数、参照関係を検証し、対象アカウントと置き換える内容を確認します
- 復元は対象アカウントの記録を一括置換します。他アカウントは保持し、失敗時は途中まで置き換えません
- 旧形式にない表示状態は通常表示へ戻します。古いJSONを復元すると、ファイルに含まれる過去の名前や履歴が戻る場合があります
- 復元だけで過去の通知を再送せず、未読はリセットします
- JSONに画像は含まれません。復元先の既存画像は原則保持しますが、完全削除済みIDとして復元した対象の画像は削除します
- 新たに取得できる画像は次回同期で補います。すでにアクセスできない画像は、JSONから復元できません

JSONの上限は25MiB、ワールド10,000件、履歴100,000件、リスト100件、表示状態10,000件です。超過時に一部の記録を黙って省略しません。

ワールド・履歴・画像は通常、自動整理しません。同期の診断記録だけをアカウントごと100件、認証前20件へ制限します。8,000ワールド、80,000履歴、概算250MiBのいずれかに達した場合は容量の注意を表示します。ブラウザから拡張を削除した場合や保存領域の故障などでは、保存済み記録を失うことがあります。

## 更新と利用終了

Windowsインストーラーは現在のWindowsユーザー専用の固定場所へ配置し、管理者権限、常駐サービス、ブラウザの強制インストールを使いません。更新時は同じ配置場所を維持し、同版の再インストールを許可し、古い版への上書きを拒否します。Chromeでの権限承認や再読み込みは利用者が行います。

利用終了時は、必要なJSONを書き出した後、拡張画面の「記録をすべて削除して拡張を削除」を実行し、Windows側のアンインストールを行います。

全消去は同期と書き込みを止め、一時Cookieの不在を確認してから、全アカウントの記録と画像を一括削除します。消去後にChrome側の削除が失敗した場合は、記録消去済みと案内して同期を止めたままにします。Windows側の削除は配置ファイルが対象です。書き出したJSONやChromeの他のデータは自動削除しません。

## 品質と検証

検証では、正常な取得だけでなく、途中終了、再試行、重複操作、アカウント切り替え、復元・削除との競合、旧形式からの移行を扱います。実装上の安全条件は[アーキテクチャ](ARCHITECTURE.md)と[セキュリティ](SECURITY.md)、自動検証とWindows実機確認の範囲は[開発ガイド](DEVELOPMENT.md)を参照してください。
